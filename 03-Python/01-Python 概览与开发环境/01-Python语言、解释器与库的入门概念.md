# Python 语言、解释器与库的入门概念

## 1. Python 语言与源代码

**Python 是一种通用编程语言，可以用来编写多种用途的程序**，例如日常自动化、网站后端、数据处理和科学计算程序。

理解 Python，需要区分三个概念：

| 概念 | 含义 |
| --- | --- |
| 语言 | 描述程序的规则体系，既规定代码可以怎样写，也规定这些写法表示什么含义 |
| 语法 | 语言中关于代码书写和组合方式的规则 |
| 源代码 | 程序员按照语言规则写出的具体程序内容 |

语言规则与源代码，可以理解为“规则”与“按规则写出的内容”的关系。编写新的程序，增加的是具体功能；程序仍然需要遵循语言已有的规则。

Python 源代码保存在文件中时，常见形式是以 `.py` 为扩展名的纯文本文件，例如 `hello.py`。纯文本文件保存的是文字内容，编辑器可以查看和修改这些文字。

`.py` 是帮助人和工具识别源代码的常用扩展名。**文件中的内容是否符合 Python 规则，仍然取决于代码本身；仅修改扩展名不会让任意文字变成合法程序。**

## 2. 一个最小的 Python 示例

```python
print("你好，Python")
```

这段代码的作用是调用 `print` 函数，输出一段文字。

**函数**是封装某项功能、可以被调用的代码单元。调用函数，就是按照语言规定的方式使用它提供的功能。

| 代码中的部分 | 含义 |
| --- | --- |
| `print` | Python 提供的一个内置函数的名称，用于输出内容 |
| `(...)` | 在这里表示调用函数，括号内给出传入的内容 |
| `"你好，Python"` | 一个字符串，即文本数据 |
| 两边的英文双引号 | 标明字符串的开始和结束；在这个例子中，不属于要输出的文字 |

预期输出：

```text
你好，Python
```

这里用来界定字符串的那一对双引号不会出现在输出中。Python 默认提供 `print`，使用这个函数不需要先写导入语句。

`print` 是具体函数的名称，函数调用和字符串的写法则属于 Python 的规则。**使用已有功能，与增加语言规则，是不同层次的事情。**

## 3. 解释器、语言实现与开发工具

### 3.1 各自的职责

| 概念         | 职责                                | 例子                   |
| ---------- | --------------------------------- | -------------------- |
| Python 语言  | 规定程序的写法和含义                        | 函数调用、字符串等规则          |
| Python 源代码 | 表达程序需要完成的具体工作                     | `print("你好，Python")` |
| Python 解释器 | 按照 Python 的规则执行具体程序               | CPython 实现中的解释器      |
| 编辑器与开发工具   | 帮助查看、编写、保存和组织代码；部分工具还提供运行、调试等辅助功能 | VS Code；记事本也可以编辑纯文本  |

**更换编辑器不会改变同一段源代码使用的语言。** 将上述代码从 VS Code 换到记事本中查看或编辑，它仍然是 Python 代码。

编辑、保存代码与执行代码是不同的操作。源代码保存下来，并不意味着它已经运行；实际执行程序需要解释器等配套软件。

### 3.2 Python 的实现与 CPython

**Python 是编程语言，CPython 是这门语言的一种具体实现。Python 的实现不只有 CPython。**

“实现一种语言”是指编写软件，使这套语言规则能够被实际支持和执行。不同项目可以采用不同的内部设计，实现执行 Python 程序的能力。

**CPython 的核心解释器主要用 C 编写。** 从 python.org 获取常规 Python 发行版时，主要接触到的就是 CPython。

这里涉及两个层次：

| 层次 | 使用的语言 |
| --- | --- |
| 用 Python 编写自己的程序 | Python |
| 实现 CPython 的核心解释器 | 主要是 C |

使用 Python 编写程序并交给 CPython 执行，不要求先学习 C。解释器本身是别人已经实现好的软件，程序员可以直接使用。

“CPython 解释器”强调其中负责执行程序的部分；“CPython 是 Python 的一种实现”是更完整的表述。

### 3.3 VS Code 与 Python 扩展

**扩展**是安装到编辑器中、为编辑器增加功能的组件。VS Code 的 Python 扩展可以提供与 Python 开发有关的辅助能力，例如代码提示、解释器选择和运行入口。

这些功能需要与实际的 Python 解释器配合。VS Code 中的运行操作，可以调用选定的解释器来执行程序。

因此，VS Code、Python 扩展和 Python 解释器承担不同职责。安装编辑器或编辑器扩展，不代表已经安装并正确配置了解释器。

## 4. 功能代码的组织与来源

### 4.1 函数、模块、包与库

这些概念描述代码的不同方面：

| 概念 | 主要含义 |
| --- | --- |
| 函数 | 封装某项功能，供程序调用 |
| 模块 | Python 组织相关代码与功能的一种基本单位，可以包含函数等内容 |
| 包 | Python 中一种特殊的模块，可以组织子模块和子包 |
| 库 | 对可复用功能代码的称呼，可以通过一个或多个模块、包提供功能 |

例如，一个包含 Python 代码的 `discount.py` 文件，可以作为模块使用，其中可以定义计算折扣的函数。模块也有其他实现形式，并不一定都是 `.py` 文件。

**所有包都是模块，但并非所有模块都是包。** ==包能够组织子模块和子包==，是 Python 对这种模块的规定；不能仅根据“它包含多个模块”来推导它也是模块。是否为包，也不取决于其中包含多少个模块：满足相应组织规则的包，即使暂时没有子模块，也仍然是包。

例如，`shop_tools` 包可以组织 `price_tools` 和 `shipping_tools` 两个模块。`shop_tools.price_tools` 表示这个包中的 `price_tools` 模块。标准库中的 `urllib.request` 同样表示 `urllib` 包中的 `request` 模块。

“模块”“包”主要描述代码的组织方式，==“库”主要强调这些代码提供可复用功能==。复用既可以发生在其他人的程序中，也可以发生在开发者自己的其他程序或项目中。

**一个普通模块就可以提供一个小型库的全部功能。** 把它称为“库”，不会使它变成“包”。某套代码也可以同时被描述为“一个库”和“通过包来组织代码”，这两个描述关注不同的方面。

“函数、模块、包、库”不是必须逐层包含的四级结构。“模块”“包”也不是“标准库”“第三方库”之外的另一套来源分类。例如，`math` 是模块，同时属于标准库；开发者自己编写的代码，也可以组织成模块、包或库。

### 4.2 标准库

**Python 标准库是 Python 官方提供、通常随常规 Python 发行版配套分发的一组功能。**

| 名称 | 主要用途 |
| --- | --- |
| `math` | 数学运算，例如求平方根 |
| `json` | 处理 JSON 格式的数据 |
| `urllib.request` | 访问网络资源，提供 HTTP 等相关能力 |

JSON 是用文本表示和交换数据的一种格式。HTTP 是网络通信的一套常用规则，网站和许多网络服务会使用它。

**标准库随 Python 配套提供，不意味着所有标准库代码都包含在单个解释器可执行文件中。**

标准库中的模块有不同实现形式：有些由 Python 编写，有些由 C 实现；有些是解释器的组成部分，有些以独立模块文件等形式提供。判断某项功能是否属于标准库，不能只看它是否位于解释器文件内部。

标准库的具体内容和可用性，会受到 Python 版本、操作系统、实现及安装配置等因素影响。**“属于标准库”不代表“在所有 Python 环境中一定存在且行为完全相同”。**

### 4.3 第三方库与自己编写的代码

**第三方库是标准库之外，由独立项目等提供的可复用功能库。** `requests` 就是提供 HTTP 请求功能的第三方库。

“是否属于标准库”取决于它是否属于 Python 的标准配套功能。即使 `requests` 随其他软件一起预装，或者早已安装在电脑上，它仍然是第三方库，安装状态不会改变其归属。

第三方库也可以提供与标准库相近的能力。例如，标准库的 `urllib.request` 同样提供 HTTP 相关功能；`requests` 提供另一套使用接口和便利功能。

程序还可以使用项目中自己编写的功能代码。自己写了一个函数，或把代码整理成库，都不会因此使它成为 Python 标准库的一部分。

### 4.4 默认可用的内置函数

**Python 默认提供一组无需先导入、就能按名称使用的函数，`print` 是其中之一。**

这一结论针对这些默认可用的函数，不能仅凭“内置”两个字推断所有功能都能直接调用。例如，**内置模块**是作为解释器组成部分提供的模块，其中的功能仍可能需要先导入模块才能使用。

判断一种功能时，需要分别考虑：

- 它是否属于标准配套功能。
- 它以什么形式实现和提供。
- 程序是否需要先导入相关模块才能使用它。

这些问题不能互相替代。也不能把“内置函数”“标准库”“第三方库”理解成三个完全互斥的类别。

## 5. 运行环境、安装、导入与依赖

### 5.1 什么是 Python 运行环境

**Python 运行环境，是程序执行时使用的解释器、可用的库及相关配置等条件的组合。** 它也会受到操作系统等外部条件影响。

日常所说的“安装 Python”，通常是在安装某一种 Python 实现提供的解释器、配套标准库等内容。

一台电脑可以有多个 Python 环境。例如，环境 A 已经安装 `requests`，不代表环境 B 也能使用它。讨论某个库能否使用时，需要明确程序使用的是哪个环境。

**依赖**是一个程序或组件正常工作时需要使用的其他库、组件等。例如，程序使用 `requests` 提供网络请求功能，那么 `requests` 就是该程序的一项依赖。

### 5.2 安装与导入解决不同的问题

| 动作 | 主要作用 |
| --- | --- |
| 安装第三方库 | 将相应代码及必要内容准备到指定的 Python 环境，使该环境具备使用它的条件 |
| 导入 | 在程序运行过程中查找模块，必要时加载和初始化，并按照导入写法引入相应名称 |

`pip` 是常用于安装 Python 第三方软件的工具。安装时需要明确目标环境；程序运行时，也需要明确实际使用的环境。

假设环境 A、B 相互隔离，只有 A 安装了 `requests`，B 中没有它，也无法从其他位置找到它。如果继续使用 B 运行程序，就需要先把 `requests` 正确安装到 B，再使用 B 执行程序中的导入语句。仅在 A 中重复安装，不能解决 B 中缺少它的问题。

**安装成功，不会自动把名称 `requests` 引入每个独立的 Python 程序。** 环境准备好以后，程序仍需要通过相应的导入操作使用它。安装是否完成，与当前代码是否已经引入相关名称，需要分别判断。

一个最小的导入示例：

```python
import math
```

这行代码中，`import` 是 Python 为导入操作规定的关键字，也就是语言赋予特殊用途的词；`math` 是模块名称。

这条语句让当前代码可以通过 `math` 这个名称使用数学模块。它本身不计算平方根，也不打印结果。

被导入的模块可以来自不同来源：

- 标准库中的 `math` 通常随正常、完整的 CPython 安装提供，不需要再单独安装。
- 第三方库需要在运行程序的环境中可用，使用安装工具是常见的准备方式。
- 自己编写的模块，处于 Python 能够查找的位置时也可以导入，不一定需要经过安装工具。

**Python 默认的导入机制不会自动下载并安装缺失的第三方库。** 如果当前环境确实找不到 `requests`，执行 `import requests` 会出现类似下面的错误：

```text
ModuleNotFoundError: No module named 'requests'
```

`ModuleNotFoundError` 表示没有找到模块；后面的文字指出没有找到名为 `requests` 的模块。修改导入写法，不能替代把所需的库准备到目标环境中。

**导入发生在程序运行过程中。** 首次加载模块时会进行初始化；对于普通 Python 模块，这通常涉及执行模块中的代码，让模块准备好工作。因此，导入并非单纯的文字声明，也不意味着自动调用模块中定义的所有函数。后续导入通常会复用已经加载的模块，而不是每次都重新加载。

### 5.3 导入、调用、返回值与输出

```python
import math
print(math.sqrt(16))
```

预期输出：

```text
4.0
```

第一行引入名称 `math`。第二行中，各部分的含义如下：

| 代码中的部分 | 含义 |
| --- | --- |
| `math` | 第一行导入后可用的模块名称 |
| `.` | 在这里用于访问模块提供的内容 |
| `sqrt` | `math` 模块中平方根函数的名称 |
| `math.sqrt` | 取得模块提供的这个函数，尚未仅凭这段写法调用它 |
| `math.sqrt(16)` | 调用平方根函数，把数值 `16` 交给它计算 |
| `print(...)` | 输出括号内交给它的内容 |

**返回值**是函数完成调用后，交回给调用处的结果。在这个例子中，先调用 `math.sqrt(16)` 得到返回值，再把这个返回值传给 `print` 输出。

`math.sqrt(16)` 的结果是 `4.0`，其类型是 `float`，也就是浮点数。浮点数可以表示带有小数部分的数值，也可以表示像 `4.0` 这样数值上为整数的结果。这里的 `.0` 来自平方根函数返回的数值类型，不是 `print` 把所有数字都改成带小数点的形式。

返回结果与输出结果是不同的操作：本例中 `sqrt` 负责计算并返回，`print` 负责把得到的内容输出。

### 5.4 两种导入写法与当前可用的名称

下面两段程序分别独立运行，都会输出 `4.0`。

第一种写法：

```python
import math
print(math.sqrt(16))
```

第二种写法：

```python
from math import sqrt
print(sqrt(16))
```

第二种写法中，`from` 和 `import` 都是关键字；`math` 指定从哪个模块取得内容，`sqrt` 指定要引入的名称。它让当前代码能够直接通过名称 `sqrt` 使用这个平方根函数。

| 导入语句 | 这条语句在当前代码中引入的名称 | 相应的调用写法 |
| --- | --- | --- |
| `import math` | `math` | `math.sqrt(16)` |
| `from math import sqrt` | `sqrt` | `sqrt(16)` |

**`from math import sqrt` 仍然需要查找 `math` 模块，并在必要时加载和初始化它，再取得其中的 `sqrt`。** 它没有同时把名称 `math` 引入当前代码，不能据此认为 Python 完全没有导入这个模块。

在没有其他导入或定义的独立程序中：

- 只写 `import math`，随后直接使用 `sqrt(16)`，会因为当前代码没有可直接使用的名称 `sqrt` 而出错。
- 只写 `from math import sqrt`，随后使用 `math.sqrt(16)`，会因为当前代码没有可直接使用的名称 `math` 而出错。

这两种情况的重点是当前代码中有哪些可用名称，和运行环境根本找不到所需模块的情况不同。

**模块能否被找到、当前代码引入了哪个名称、函数是否已经被调用，是三个需要分别判断的问题。** 两种导入写法调用的可以是同一个函数；导入写法不会改变函数原本提供的功能。

### 5.5 解释器与标准库可以存在依赖

**解释器与标准库承担不同职责，并不意味着它们在实际运行时完全独立。**

例如：

```python
print("你好，Python")
```

这段代码没有导入语句，只能说明程序没有显式导入模块。它不能证明解释器的启动和运行完全不需要标准库。

常规 CPython 在启动时需要建立导入、文字编码等基础能力，并使用相应的配套组件。例如，标准库中的 `encodings` 提供文字编码支持，与文字的存储和转换有关。缺少启动所必需的组件，解释器可能在用户代码开始执行之前就启动失败。

这也不意味着每个程序都会使用整个标准库。根据具体实现和程序需要，可以构建保留必要组件的精简环境；这样的环境仍然需要满足启动和运行所需的依赖。

因此，“用户代码没有显式使用某项功能”“运行环境不需要它”“整个标准库都可以删除”，是不同的判断，不能相互推导。

## 6. 不同 Python 实现与版本

### 6.1 代表性实现

不同实现可以面向不同的使用场景。下面列出几个代表性项目，并非全部实现：

| 实现 | 主要侧重点与必要边界 |
| --- | --- |
| CPython | 使用广泛的 Python 实现，常用于普通电脑和服务器上的开发；核心解释器主要用 C 编写 |
| PyPy | 通用 Python 的另一种实现，以执行效率和兼容性为重要目标；不能保证所有程序都比在 CPython 中运行得更快 |
| MicroPython | 面向微控制器等资源受限设备的精简实现；微控制器是小型设备中承担控制任务的芯片。其语言功能和标准库与 CPython 存在差异 |
| Jython | 在 Java 平台上运行，可与 Java 类库配合；Jython 2.7 系列支持的是 Python 2，不能据此认为它支持现代 Python 3 程序 |
| IronPython | 与 .NET 软件平台集成的 Python 实现，可使用该平台的功能；需要按具体版本确认 Python 语言及库的支持情况 |

这些实现的区别不只是名称不同。它们支持的 Python 版本、语言功能、标准库和第三方库都可能不同。

### 6.2 实现名称与语言版本

**Python 的实现与 Python 的版本是两个不同维度。**

| 表述 | 说明的内容 |
| --- | --- |
| Python | 编程语言的名称 |
| Python 3.10、Python 3.12 等 | Python 语言的不同版本 |
| CPython、PyPy 等 | Python 的不同实现 |

某个实现还可以有自己的软件发布版本号。例如，PyPy 7.3.17 的发布中包含支持 Python 3.10 的版本：`7.3.17` 是 PyPy 自身的发布版本，`3.10` 是它支持的 Python 语言版本。两者不是同一层次的编号。

因此，仅知道“用的是 PyPy”或“用的是 Python 3”，还不足以判断某段程序能否运行。还需要确认具体版本，以及所用语言功能和依赖是否得到支持。

### 6.3 兼容性与实现细节

**兼容性**关注的是：一段程序及其依赖，在另一种实现或环境中能否按预期工作。

例如，MicroPython 提供的标准库范围较小，某个在 CPython 环境中可用的模块，在 MicroPython 中可能不存在或功能有所不同；语言层面的差异也可能影响程序运行。

Python 的语言规则与某个实现的内部机制需要分开理解。资料中标明的“CPython 实现细节”，不能直接当成所有 Python 实现都必须采用的做法。

“解释器”描述的是执行程序的职责，不能仅凭这个名称，就认定它的内部一定是逐行直接执行源代码。不同实现可以采用不同的处理方式。

## 7. 使用库为什么不会增加语言语法

假设开发者用 Python 编写一个计算折扣的函数，交给同事调用。

新增的是**一个已经实现的功能**。同事调用它时，仍然遵循 Python 已有的函数调用规则，Python 的语法没有因此改变。

`requests` 也是如此：它提供已经实现的 HTTP 相关功能，其他程序通过调用来使用。库中的 Python 代码也遵守 Python 的规则；能够参与执行的代码，不等于语言规则本身。

一个获取并处理网络数据的程序，可以组合以下功能：

1. 调用 `requests` 获取服务器返回的响应内容。
2. 如果响应文本符合 JSON 格式，使用 `json` 处理。
3. 由自己的业务代码决定提取哪些信息。
4. 使用 `print` 输出结果。

在这样的程序中，解释器承担执行职责，库提供可复用功能，业务代码决定如何组合这些功能。三者配合完成程序的工作。

## 8. Python 生态的基本组成

**Python 生态指围绕 Python 的开发与使用形成的项目、工具、资料和社区。** 语言本身是其中的一部分。

| 组成 | 主要作用 |
| --- | --- |
| 语言实现与运行环境 | 使 Python 程序能够实际执行，例如使用 CPython 的环境 |
| 标准库与第三方库 | 提供可复用功能，例如 `math`、`json` 和 `requests` |
| 编辑器与开发辅助工具 | 帮助编写、组织、运行和调试代码，例如 VS Code 及相关扩展 |
| 文档与社区 | 提供使用说明、问题讨论，以及项目的开发和维护 |

这些部分互相配合：使用编辑器编写遵循语言规则的代码，借助库实现功能，再交给具备所需组件的运行环境执行。
