# 一、回答重点

上下文窗口（Context Window）是指大语言模型一次能够处理的最大 Token 数量，包括输入的提示词和输出的内容。

不同模型的上下文窗口大小差别很大。早期的 GPT-3 只有 4096 个 Token，GPT-3.5-turbo 有 4096-16K 个Token，GPT-4 有 8K-128K 个 Token，Claude 3 更是达到了 200K 个 Token。模型越新、越强大，上下文窗口一般越大。

上下文窗口的限制主要体现在三个方面。首先是内容长度限制，如果提示词加上期望的输出超过了窗口大小，模型就无法处理，会报错或截断。其次是历史对话限制，在多轮对话中，所有历史对话都占用上下文窗口，聊的越久，能处理的新内容就越少。最后是成本限制，上下文窗口越大，调用成本越高，而且相应速度可能也会变慢。

# 二、扩展知识

理解上下文窗口对实际应用很重要。比如做文档分析，一份 5 万字的文档可能有 7-10 万个 Token，如果模型的上下文窗口只有 4K，就必须分段处理，不能一次性分析整份文档。这时候要么换用更大窗口的模型，耀目设计分段处理的策略。

在聊天机器人场景中，上下文窗口管理是个很关键的问题。随着对话进行，历史消息越来越多，很快就会占满窗口。常见的解决方法有几种：只保留最近 N 轮对话；用摘要替代历史对话；提取关键信息而不是保留全部对话；根据相关性动态选择保留哪些历史。

上下文窗口不是越大越好。虽然大窗口能处理更长的任务，但也带来问题。一是成本高，按 Token 收费意味着大窗口很贵。二是响应慢，处理更长的上下文需要更多计算时间。三是注意力分散，当上下文很长时，模型对中间部分的理解会变弱，这叫 =="中间丢失" ==问题。

有个实用技巧是把重要信息放在开头或结尾。模型对提示词开头和结尾的部分注意力最集中，对中间部分相对较弱。所以关键指令放开头，重要数据放结尾，效果会更好。

上下文窗口越来越大，但是这不意味着可以无限使用，成本和效率还是要考虑的。合理设计提示词结构，精简不必要的内容，依然是重要技能。

在开发 AI 应用时，要根据模型的上下文窗口来设计功能。如果需要处理长文档，要么选择大窗口模型，要么实现文档切分和合并的逻辑。如果做多轮的话，要实现好历史管理机制。提前规划好，才不会在实际使用时遇到瓶颈。
